# Run only in a fresh isolated native window with sessions-sidebar linked and an active shell tab
# (any display mode). From the plugin folder:
# tern ctl --control <endpoint> --file tests/reattach.txt
# A remote host that goes away and attaches again (a boat sandbox's Stop and Start, Resize, Remove
# from Tern and Connect) comes back with the same tab and pane ids, and Tern 0.9.5 reports no
# pane_closed or tab_closed when it goes. Before 1.11.1 the sidebar kept its state for those ids: the
# returning tab got no sidebar (taken for hidden) or kept a frozen one, with "The sidebar canvas is
# not available in this window". Through the fake boat-sandbox script of boat-sandbox.txt, a
# loopback host tracked as Boat Sandbox (re) is removed with Remove from Tern, attached again,
# disconnected by Tern and attached again (`remote loopback` stands in for Connect, which cannot
# reach a loopback host), while the listing changes each time. The returning tab must show exactly
# one sidebar drawn from the newest listing (Show details on: the row's second line), with the
# sandbox as its one current row and none of its host's sessions; the listing must be read again
# (also by an ordinary refresh a minute later) and Tern's log must hold no sidebar error or hook
# overrun. Adds one loopback remote host and disconnects it; removes its fake files, records and
# cache and puts back the hook it found. Selectors start with `.tn-pane:not(.off)`: hidden tabs keep
# their sidebars off screen.
