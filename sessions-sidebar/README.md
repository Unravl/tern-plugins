# Sessions Sidebar for Tern

A native **Sessions** list on the left of each tab: every session grouped by host (**This PC** first, then attached remote hosts), with icons, names, working directories and what each session's omp agents are doing, and a **Boat sandboxes** section on top that manages every boat.dev sandbox and snapshot of your account, one row per sandbox (create, start, stop, resize, duplicate, auto-stop, snapshots, SSH details, delete), and shows your plan's compute usage. Click a row to switch. Files: `plugin.toml`, `window.luau` (the entry: commands and hooks), `core.luau` (canvases, refresh, docked width, lifecycle), `actions.luau` (clicks, menus, inputs, add-host requests), `sessions.luau`, `session-data.luau`, `boats.luau`, `boat-view.luau`, `boat-ui.luau`, `agents.luau`, `drawer.luau`, `docked.luau`, `tsp.luau`, `sidebar.css`, `drawer.css`.

## Install

Requires a Tern desktop app; built and verified on **Tern 0.7.3**. The `tern` command is the app's executable (`/Applications/Tern.app/Contents/MacOS/tern` on macOS) if it is not on your PATH.

From a copy of this folder (for example an unzipped download):

```sh
tern plugin install ~/Downloads/sessions-sidebar
```

From the [tern-plugins](https://github.com/Unravl/tern-plugins) repository, where this plugin is the `sessions-sidebar` folder. The repository is private, so this needs a GitHub account with access to it and git credentials on that machine:

```sh
tern plugin install github.com/Unravl/tern-plugins/sessions-sidebar
```

`install` copies the plugin into Tern's plugins folder (`tern plugin dir`) and reloads plugins; the sidebar appears in each tab you open or visit. `tern plugin list` should show `sessions-sidebar 1.12.0 … ready`. To update, run the same command with `--force`; to uninstall, `tern plugin remove sessions-sidebar`.

To develop, use the folder in place instead: `tern plugin link ~/Documents/tern-plugins/sessions-sidebar`. After editing, reload with **`tern plugin reload`** from a terminal (see [Known limits](#known-limits) for why not the palette's *Reload plugins*).

## Display modes

Open **Sessions sidebar settings** from the gear in the sidebar header or the command palette:

| Mode | Behavior |
| --- | --- |
| **Hover left edge** (default) | A thin strip on the window's left edge. Moving the pointer onto it slides the drawer out **over** the content; it stays while the pointer is inside and closes when it leaves. |
| **Click tab** | A small tab on the left edge. Click it to open the drawer over the content; click it again to close. |
| **Always expanded** | The sidebar is docked as a normal left split and takes its own space. Drag its divider to the width you want: it stays exactly where you let go, and every tab, session and remote host gets that same width, so switching never moves the column and new tabs and sessions open with it. Only a drag changes the width. **Even out splits** (⌃⌘=) evens the other panes and leaves the sidebar alone, and a font size change keeps its width in pixels. When the window (or its tab area) changes width, the column keeps its width in terminal cells: it settles back within a second or two, to the nearest cell, because Tern exposes pane widths only in whole cells. Tern never lets a split be narrower than 10% of the window, so in a window more than ten times the sidebar's width the column grows to that 10%. |

The two overlay modes never resize the terminal or other panes: the drawer floats above them and leaves no gap when closed. While a prompt, picker or confirmation of the sidebar is open, the drawer stays open. The chosen mode is saved and applies to every tab.

Row icons sit **5 px from the drawer content's left edge**, with no grips on session rows or host headers. Tern's native **10 px docked canvas inset** remains in Always expanded mode; the 5 px spacing is relative to sidebar content, not the visible window edge.

## Using the list

- **Switch:** click a session row. Switching uses the exact numeric session ID, so duplicate names (also across hosts) are safe. The current session is highlighted; clicking it only returns focus to the terminal and never changes tabs. Clicking a session on another host switches host too.
- **Collapse a host:** click the **-** / **+** button left of a host title. Collapsed hosts are remembered.
- **New session on a host:** click the **+** icon at the far right of a connected host's header. It asks for a name, creates the session on that host and switches to it; blank or cancelled does nothing.
- **Reorder sessions and hosts:** Tern 0.7.3 plugin panels cannot be dragged with the mouse, so moving is pick and place. Right-click a session row or host title and choose **Move session** / **Move host**. The item lifts (accent bar) and a banner appears; click the session or host header whose place it should take. Moving down lands just after that item, moving up just before it. Click the lifted item again or **Cancel** to stop. Sessions move within their own host; hosts (including **This PC**) move among hosts. Boat sandboxes keep their own order (by name) in their section and are not moved. While an item is lifted the drawer stays open in the overlay modes.
- **Right-click a session:** **Rename session**, **Move session**, **Change icon**, **Reset icon**. Renaming does not switch to the session and keeps its icon and position.
- **Right-click a host title:** **New session** (same as the **+** icon; hidden while the host is not connected), **Move host**, **Rename host title**, **Reset host title**, **Change title color** and, for a remote host, **Remove host…** (see [Remote hosts](#remote-hosts)). A boat sandbox's host has no host title: its row in the Boat section stands for it, with the sandbox's own menu (see [Boat sandboxes](#boat-sandboxes)). The host title is a display alias in the sidebar only; the host's connection, address and Tern's own name are unchanged.
- **Change a host title's color:** right-click the host title and choose **Change title color**. Pick Red, Orange, Yellow, Green, Teal, Blue, Purple or Pink, **Custom hex color** (`#rgb` or `#rrggbb`, with or without `#`), or **Default color** to return to the theme's heading color. Only the title text changes; the toggle and **+** keep theme colors.
- **Change an icon:** click a session's icon (or use its menu). Pick a native icon (Terminal, Folder, Code, Branch, Server, Database, Globe, Rocket, Moon, omp, Python, Rust), **Custom glyph or emoji** (up to 64 UTF-8 bytes), or **Reset icon**. Choosing an icon does not switch sessions.
- **Paths:** the line under each name is the session's working directory. Paths in your home directory show as `~/…` (`/Users/<you>/…` locally, `/home/<you>/…` on Linux hosts). Long paths drop leading folders (`…/project/src`); hover a path for the full text.

Other palette commands: **Show sessions sidebar**, **Hide sessions sidebar (current tab)**, **Refresh sessions sidebar**, and **Add remote host from request file (scripts)** for scripts (see [Adding a host from a script](#adding-a-host-from-a-script)). There are no default shortcuts; bind `plugin.sessions-sidebar.show`, `.hide`, `.refresh` or `.settings` in your Tern keybindings if you want them. Hide (or closing the sidebar pane) keeps that tab's sidebar hidden until Show, a plugin reload or a new window.

The sidebar never keeps a tab open on its own. When a tab's last other pane closes (for example its shell exits), is parked or moves away, the sidebar closes too and Tern closes the tab, so no tab is left titled **Sessions Sidebar [ss-…]**. Loading the plugin also closes any such leftover tabs.

Session renames, creation and closing appear within about a second; **Refresh sessions sidebar** forces an immediate update.

## Agent status

The right end of a session row shows what the omp agents in that session's tabs are doing, in large bold marks:

| Mark | Meaning |
| --- | --- |
| **?** (amber) | An agent is asking a question and waits for your answer (for example omp's ask prompt). |
| Spinner | An agent is working. |
| **✓** (green) | An agent finished a task (its turn ended) and you have not visited its tab since. |

Nothing shows when the session's agents are idle and you have seen how they ended, and nothing marks the session you are on: its row highlight does that. Plain shell commands show nothing.

The spinner is live: it shows whenever an agent in the session is working, also in the tab you are looking at. **?** and **✓** wait for you. Visiting the agent's tab clears them: switching to that tab, or to its session when that tab is the one the session shows. They come back only when that agent asks again or finishes another task, and an agent in the tab you are looking at never gets one. When an agent with a **✓** starts working again, the spinner replaces the tick. A **?** also goes away when the question is answered elsewhere. A session with several agents can show more than one mark (in the order **?**, spinner, **✓**); hover a mark for how many agents it stands for.

Agents are Tern agent blocks and shells where `omp` was typed at the prompt, on This PC and on attached remote hosts. Marks follow each agent's progress and Tern's unseen-alert flag as this window sees them, within about a second. They belong to the window and are not saved; after a plugin reload, a finished turn Tern still holds as unseen (its pane has not been focused) shows its tick again.

## Boat sandboxes

The **Boat sandboxes** section at the top of the list manages every [boat.dev](https://boat.dev) sandbox and named snapshot of your account through the script `~/bin/boat-sandbox` (v2). It appears once the script has listed your account or a sandbox is tracked, so it stays hidden where boat is not set up. Its header holds a **⋯** button with **New sandbox…**, **Defaults…**, **Refresh** and **Show details** (right-clicking the header or the **+** shows the same menu) and a **+** that opens **New sandbox…**. Under it sit the usage bar, one row per sandbox (by name), any sandbox being created, and **Snapshots**.

- **Listing:** the plugin reads `boat-sandbox --inventory` (sandboxes, snapshots, plan usage, environments and defaults in one call) in the background: when a sidebar shows, on **Refresh** (or **Refresh sessions sidebar**), a few seconds after every operation, and otherwise at most once a minute while a sidebar is visible, backing off to 2, 4, 8 and at most 15 minutes while it fails. The last listing is cached, so a new window or a reload draws it at once. When a read fails, the section keeps the last listing with a muted **Not refreshed since …** line; hover it for the script's error.
- **Usage bar:** your plan's compute used this billing period against what it includes, as a thin bar over a label like `127.2 h of 555.6 h · resets Nov 15` (hours to one decimal, `+N h extra` when prepaid pack time is left). The bar is the accent color, amber from 80% and red from 95% or when boat blocks new starts. Hover it for the exact figures, the sandboxes running now and their live usage, the starts left today and this hour, extra credit and your plan.
- **One row per sandbox.** A sandbox the sidebar tracks (created or connected from it, or made by omp `/boat`) shows under its sidebar name: **demo** for the title Boat Sandbox (demo), or the name **Rename…** gave it; any other under its boat name (same-named ones get ` · <id>`) until you connect it from the sidebar, which tracks it as Boat Sandbox (<name>). A sandbox's host never shows as an ordinary host group and its sessions (such as `Default`) are not listed: the row stands for it. The row is muted unless the sandbox is attached in this window and has a badge unless it runs: **creating**, **connecting**, **starting**, **stopping**, **resizing**, **saving**, **updating** or **deleting** (with a spinner; actions that would conflict wait), **stopped** (muted), **error** (red; hover for why) or **gone** (tracked but no longer in your account; **Forget** drops it). It shows the omp agent marks of all its host's sessions together, as a session row does, and while the current session is on its host it is highlighted like the current session's row. Hover a row for its state, size, auto-stop time, environment, creation date, compute, address and what a click does.
- **Click a row** to go into the sandbox. Attached here, it switches to its session: the only one, the one Tern last showed there when it has several, or a new one named after the sandbox when it has none. Running but not attached here, it is connected first (as **Connect** below) and then switched into. A click on a stopped, busy or gone sandbox does nothing; right-click it instead.
- **Show details** (in the **⋯** menu; once on, the right-click menus offer **Hide details**) puts a second line under each name: size · `stops in 5 h` or `no auto-stop` (running) or `stopped 2 h ago · disk kept until Nov 4` (stopped; amber within 3 days, red once the disk is gone) · cost since it was created. The choice is saved and every window follows it; while it is off, that line is in the row's tooltip.
- **New sandbox…** is a summary picker that works as a form, filled in from your defaults: **Create Boat Sandbox (<name>)** first, then **Name**, **Snapshot** (your named snapshots), **Size** (small 2 vCPU · 4 GB RAM · 12 GB disk · $0.018/h; default 4 · 8 · 50 GB · $0.036/h; large 8 · 16 · 125 GB · $0.072/h; xlarge 16 · 32 · 251 GB · $0.20/h, which needs the $100+ plan and is refused with a toast on smaller plans), **Auto-stop** (1 hour, boat's default; 4 hours, 8 hours, 24 hours, 3 days, 7 days, 30 days, **Never**, or **Custom…** 1–720 hours), **Environment** (your account's default or a named one), **Secrets** (yours, or none: `--no-env`) and **Save as defaults**. Each choice returns to the summary; Esc closes it and creates nothing. **Create** without a name asks for it first (1–40 letters, digits, spaces, `.`, `_` or `-`, not starting with `-`). The plugin runs `boat-sandbox --no-tern --from <snapshot> --type <size> --hours <N>|--no-auto-stop [--environment <name>] [--no-env] <name>` (the name is one argument), shows a **creating** row with a spinner, then adds the host to this window, tracked as **Boat Sandbox (<name>)** and listed as <name>, trusting only the host key the script read from the sandbox. Toasts say when it starts and how it ended, with the script's error on failure. It takes a minute or two.
- **Right-click a running sandbox:** **Connect** (when it is not attached here: attach it here; it keeps its host key), **Save snapshot…**, **Duplicate…**, **Auto‑stop…**, **Resize…**, **Open SSH terminal** (a local tab running `boat ssh <id>`), **Copy SSH details…** (below), **Open desktop** (the sandbox's browser desktop, through a one-time link), **Copy sandbox ID**, **Rename…** (the name the sidebar shows: it starts from that name, and a blank name goes back to the sandbox's own), **Change title color** (attached here; it colors the name), **Remove from Tern** (disconnects it here; the sandbox keeps running and stays listed with Connect), **Stop…** and **Delete…**. There is no **New session**: a click on the row goes into the sandbox.
- **Right-click a stopped sandbox:** **Start**, **Start as size…**, **Save snapshot…**, **Duplicate…**, **Copy sandbox ID**, **Rename…** and **Delete…**. While an operation runs, only Copy sandbox ID and Rename… are offered.
- **Copy SSH details…** runs `boat-sandbox --ssh <id> --name <name>` (a toast says **Getting SSH details…**; it takes a few seconds), which authorizes boat's SSH key on the sandbox and pins the sandbox's host key in `~/.ssh/boat/<id>.known_hosts`, then offers four texts to copy: **SSH command** (`ssh -i ~/.ssh/ascii_box_ed25519 -o IdentitiesOnly=yes -o HostKeyAlias=<id> -o UserKnownHostsFile=~/.ssh/boat/<id>.known_hosts -p <port> user@<host>`), **SSH config entry** (a `Host boat-<name>` block with the same settings, for `~/.ssh/config`, VS Code or Cursor), **Connection details** (host, port, user, key, host key and sandbox id, one per line) and **boat ssh command** (`boat ssh <id>`). A sandbox's address and host key change when it starts again or is resized, so copy them again after a Start, Start as size or Resize. When the script fails, a toast carries its error and nothing is copied.
- **Save snapshot…** suggests `<name>-<yyyymmdd-hhmm>`. boat takes 1–63 lowercase letters, digits and `-`, not starting with `-`: capitals you type are saved lowercase, and a name with anything else (`_`, `.`, spaces) is refused with a toast before anything runs. A name you already have asks before replacing it (**Cancel** first), then runs `boat-sandbox --snapshot <id> <name> --replace`; so does the script's own `snapshot exists:` answer. A pending row shows under Snapshots while it saves.
- **Duplicate…** is the same kind of form (**Duplicate as …**, **Name**, **Size**, **Auto-stop**) for `boat-sandbox --fork <id> --type <size> --hours <N>|--no-auto-stop <name>`: a new sandbox from the source's latest snapshot, created and connected like a new one.
- **Auto‑stop…** shows the time left and offers **Stop in** 1 hour … 30 days, **Never** or **Custom…**: `boat-sandbox --extend <id> --hours <N>` sets the time left from now; Never runs `--no-auto-stop`.
- **Resize…** picks a size, asks to confirm the restart (**Cancel** first), disconnects it, runs `boat-sandbox --resize <id> --type <size>` (stop, then start at that size) and attaches it again. **Start as size…** starts a stopped sandbox at another size (`--resume <id> --type <size>`).
- **Stop…** asks first, stops it (`--stop`) and disconnects its host; it stays listed, muted and **stopped**, under its name, and no longer uses compute. **Start** runs `--resume`, which also reopens UDP 8376 (boat rewrites the sandbox's firewall on every start), and attaches it again under the same name; at a new address its name, its color and its sessions' order and icons move along. **Delete…** asks first (**Cancel** first), disconnects the host, deletes the sandbox with its disk (`--delete`) and forgets it and its saved preferences.
- **Snapshots** is a folding list (the fold is saved) of your named snapshots with size and date, headed `2 of 10 free` (plus the monthly price once over the free ten); the one new sandboxes start from is marked **default**. Click a snapshot to open New sandbox from it; right-click for **New sandbox from this…**, **Set as default**, **Copy name** and **Delete snapshot…** (**Cancel** first; it says so when the snapshot is your default).
- **Defaults…** is the same kind of form (**Snapshot**, **Size**, **Auto-stop**, **Environment**, **Secrets**, then **Done**), saved with `boat-sandbox --set-defaults`. New sandbox… and omp `/boat` both start from these defaults (the script's `~/.config/boat-sandbox/defaults.json`).
- **Sandboxes made by the omp `/boat` command** are tracked too: `~/bin/boat-sandbox <name>` puts a `boat` field in its add-host request (see [Adding a host from a script](#adding-a-host-from-a-script)).

Requirements and limits:

- Needs the `boat` CLI (signed in), [Bun](https://bun.sh) and `~/bin/boat-sandbox` v2. The plugin runs only that script, never `boat` itself. Tern started from the Dock has none of their folders on its PATH, so it runs `/usr/bin/env bun ~/bin/boat-sandbox …` with `PATH` set to `~/.ascii/bin`, `~/.bun/bin`, `~/bin`, `/opt/homebrew/bin`, `/usr/local/bin` and the system folders. The script prints one JSON summary on its last stdout line (documented in its `--help`).
- Sandboxes are paid while they run; xlarge needs the $100+ plan. Named snapshots are free up to 10, then $1.70 a month each. boat keeps a stopped sandbox's disk for 14 days; Start fails after that.
- Operations run in the background and belong to the window that started them: closing it or reloading the plugin while one runs loses the spinner and the result toast (the script carries on). A sandbox created that way is not tracked but is listed under its boat name; **Connect** tracks it. Other windows see only the states boat reports. Sandbox records and the listing cache are shared by all windows.
- Attaching waits at most 60 seconds for Tern to connect. A sandbox that takes longer shows **error**; **Connect** tries again.
- boat cannot rename a sandbox: **Rename…** changes the name the sidebar shows only.

## Remote hosts

Only hosts already attached to this window are listed: **This PC** first and remote hosts alphabetically until you reorder them; boat sandboxes are listed in their own section. Nothing is installed on the remote, and apart from the Boat section's `~/bin/boat-sandbox` runs the plugin runs no shell, SSH or network commands of its own; the remote Tern service must support native canvas panes. Disconnecting and forgetting a host removes its group.

**Remove host…** (right-click a remote host's title) asks first (**Cancel** first), then disconnects the host, so Tern forgets it, and forgets the sidebar's saved title, title color, folding, place, session order and icons for it. Programs on the host keep running. For a boat sandbox use **Remove from Tern**, which keeps the sandbox tracked.

### Adding a host from a script

The window action `plugin.sessions-sidebar.add-host` (palette: **Add remote host from request file (scripts)**) attaches a remote host under a title of the caller's choosing, through the same path New Boat Sandbox and Start use. It is meant for scripts such as the omp `/boat` command, which runs `~/bin/boat-sandbox <name>` to create a boat.dev sandbox titled **Boat Sandbox (<name>)** (its Boat section row shows <name>). The script writes a request to `add-host.json` in the plugin's data folder (`$TERN_CONFIG_DIR/plugin-data/sessions-sidebar`, by default `~/Library/Application Support/Tern/plugin-data/sessions-sidebar`), then runs `tern ctl plugins run plugin.sessions-sidebar.add-host` (add `--control <endpoint>` to pick a window; without it, run from a Tern pane, the window showing that pane does it):

```json
{"id":"boat-1729000000","address":"user@2001:db8::27","title":"Boat Sandbox (demo)","fingerprint":"SHA256:…","boat":{"id":"bx_abc123","name":"demo"}}
```

`address` is what Tern's Add remote host takes (`[user@]host[:port]`, IPv6 without brackets when there is no port); `fingerprint` is the host key from `tern remote host-key` on that machine. `boat` is optional: with it, the connected host is recorded as that boat.dev sandbox (`id` a `bx_…` sandbox id, `name` its 1–40 character name), so it joins the [Boat sandboxes](#boat-sandboxes) section as one row named after `title` (Boat Sandbox (<name>) shows as <name>). The plugin deletes the request when it picks it up, saves `title` as the host's title alias (the same one **Rename host title** sets, keyed by the address) and asks Tern to add the host. A first-contact host key is trusted only when it equals `fingerprint`; any other key fails the request and is never trusted. A host that is already attached is not added again. Once the host is connected, has failed, or 60 seconds have passed, the plugin writes `add-host.result.json` beside the request:

```json
{"id":"boat-1729000000","ok":true,"state":"connected"}
{"id":"boat-1729000000","ok":false,"state":"verify","error":"host key SHA256:… does not match the expected SHA256:…"}
```

`id` repeats the request's, so a script polls for its own result; `state` is the host's last state, or `invalid` for a request that could not be used (not JSON, no `id`, a blank title, a blank address or one with spaces, a fingerprint not starting with `SHA256:`, or a `boat` without a `bx_…` id and a valid name; an unreadable `id` comes back as `null`). A failed request also shows an error toast, and a host it added is disconnected rather than left failed or waiting for verification. Without a request file the action does nothing. Progress belongs to the window: a plugin reload while a request is pending drops it without a result, so scripts should give up after their own timeout (a little over the plugin's 60 seconds). The sidebar refreshes itself once a request finishes; a script may also run `plugins run plugin.sessions-sidebar.refresh` afterwards, which still works if Tern has stopped the plugin's timers after an overrun.

## What is saved

Saved in Tern's plugin storage and kept across reloads and restarts: display mode, docked sidebar width (in terminal cells at the font size it was set at, plus its share of the window, which a new window starts from), collapsed hosts, host order, session order, host title aliases, host title colors, session icons, boat sandbox records (sandbox id, name, title, last address, running or stopped, last error, when saved), the last boat listing (`sidebar.boat-inventory.v1`: the script's `--inventory` answer and when it was read, shared by windows and redrawn at once after a reload), whether Snapshots is folded and whether the Boat section shows details (`sidebar.boat-details.v1`). Agent status and operations in progress are not saved; the boat defaults live in the script's own file, not in Tern. Hosts are identified by `This PC` or the remote's address (else its name), never by window-local IDs; a host that is detached keeps its saved place for when it returns, and a boat sandbox's preferences follow it to a new address.

Session icons and positions are saved by host plus session name, so they follow a session when you rename it through the sidebar. A session renamed elsewhere, or created later, appears after the ordered ones until you move it. If two sessions on the same host share a name, their icons and positions are kept only for the current window and are not saved; a session never inherits another session's icon (for example after the original of a duplicate name closes).

## Known limits

- **Prefer `tern plugin reload` to the palette's *Reload plugins*.** The palette action (and sometimes restarting Tern) makes Tern drop the state of existing plugin canvases: each sidebar becomes a blank pane titled **Canvas**, and a tab whose focused pane is one shows as **Canvas** in the tab bar. The plugin closes every such blank canvas, in any tab or session of the window, once it has had no state for five seconds, and the tab you are in gets a working sidebar again; other tabs get theirs when you visit them. Blank canvases left by older versions are closed the same way. The CLI reload, source-file reloads and session switches do not drop canvas state.
- The overlay modes style the floating panel through the accessible label Tern 0.7.3 gives plugin canvases (`Sessions Sidebar [ss-…]`). That is not a documented, stable SDK hook; if a future Tern changes it, use **Always expanded**, which needs no such styling.
- In **Always expanded** mode in a tab with vertically stacked splits, the sidebar fills the height of the leftmost column only; existing splits are never flattened. Likewise, a sidebar opened or docked in a tab that already has several columns (by Show, a mode switch or Reload plugins) sits inside the leftmost column, which Tern does not let it fill; if that column is too narrow for the docked width, drag its divider wider and the sidebar takes the docked width again.
- In **Always expanded** mode Tern's own **Even out splits** is kept from resizing the sidebar through its command (key binding, palette or action). Tern scripts and other plugins that even out a tab directly do resize it, and the sidebar then takes that width as if dragged.
- Agent status needs Tern's agent support (`cx.agents`, verified on **Tern 0.8.2**); without it rows show no marks. A turn too short for the one-second refresh to see it working shows no spinner; its tick comes from Tern's unseen alert, so if omp sends no completion alert such a turn shows no tick either. Tern's `agent_finished` event does not fire for these agents in 0.8.2 and is not used.
- Tern gives each call of a plugin hook a 50 ms budget. When one call runs past it, Tern logs `plugin hook exceeded its budget; disabled until reload` and that hook stays off until the plugin reloads or Tern restarts; quitting and reopening Tern always restores it. With the click hook (`canvas_action`) off, every sidebar click answers *Nothing handles "switch-session" here*. Since 1.8.1 the sidebar keeps its calls far below the budget.
- The load hook has the same 50 ms, and a reload that runs past it leaves the plugin unloaded (`load exceeded 50 ms`). So loading only registers the commands and hooks; the modules compile afterwards, each in a callback of its own: `core.luau` and `actions.luau` after the modules they need, `boat-view.luau` too when the Boat section has something to show, and `boat-ui.luau` (the section's menus and forms) right after `boat-view.luau`. Until then a click on a sidebar drawn before the reload does nothing and commands wait for the modules. A module that fails to load shows the toast **Plugin Sessions Sidebar failed to load** with the first line of the error, and the sidebar stays off until the next reload. When only `boat-view.luau` fails, Tern's log says why and the rest of the sidebar loads without the Boat section; sandbox hosts still never show as ordinary host groups.
- Desktop windows only: Tern's web client has no window Lua runtime.

To remove the plugin, hide or close the sidebars, then run `tern plugin remove sessions-sidebar` (or `tern plugin unlink sessions-sidebar` for a linked development copy). Removing it does not close sidebar panes that are still open.

Run them from this folder in a **fresh isolated window**, never your normal sessions. The window below starts hidden in the background, so it does not take focus:

```sh
test_dir="$(mktemp -d /tmp/tern-sidebar-test.XXXXXX)"
export TERN_CONFIG_DIR="$test_dir/config" TERN_DAEMON_SOCKET="$test_dir/daemon.sock" STENCIL_LOG_DIR="$test_dir/logs"
mkdir -p "$TERN_CONFIG_DIR/omp" && printf '{"managed":false,"checked":0,"no_build":false,"offered":true}' > "$TERN_CONFIG_DIR/omp/state.json"
mkdir -p "$TERN_CONFIG_DIR/plugin-data/sessions-sidebar"
printf '%s\n' 'echo "{\"ok\":false,\"error\":\"no boat in this test window\"}"; exit 1' > "$test_dir/no-boat.sh"
printf '{"sidebar.boat-commands.v1":{"script":["/bin/sh","%s"]}}' "$test_dir/no-boat.sh" > "$TERN_CONFIG_DIR/plugin-data/sessions-sidebar/kv.json"
rsync -a --exclude tests ./ "$test_dir/sessions-sidebar/"
tern plugin link "$test_dir/sessions-sidebar"
open -g -j -n --env TERN_CONFIG_DIR="$TERN_CONFIG_DIR" --env TERN_DAEMON_SOCKET="$TERN_DAEMON_SOCKET" --env STENCIL_LOG_DIR="$STENCIL_LOG_DIR" \
  -a /Applications/Tern.app --args --control "$test_dir/control.sock" /tmp -NSAppSleepDisabled YES
until [ -S "$test_dir/control.sock" ]; do sleep 0.5; done
tern ctl --control "$test_dir/control.sock" --file tests/session-switch.txt
tern ctl --control "$test_dir/control.sock" --file tests/sidebar-lifecycle.txt
tern ctl --control "$test_dir/control.sock" --file tests/agent-markers.txt
tern ctl --control "$test_dir/control.sock" --file tests/add-host.txt
tern ctl --control "$test_dir/control.sock" --file tests/remove-host.txt
tern ctl --control "$test_dir/control.sock" --file tests/docked-width.txt
tern ctl --control "$test_dir/control.sock" --file tests/boat-sandbox.txt
tern ctl --control "$test_dir/control.sock" --file tests/boat-forms.txt
tern ctl --control "$test_dir/control.sock" --file tests/reattach.txt
tern ctl --control "$test_dir/control.sock" --file tests/boat-rows.txt
```

The `state.json` line stops a fresh config from offering to install omp (and linking it into `~/bin`). The `no-boat.sh` lines set the test-only kv key `sidebar.boat-commands.v1` (`{"script": [argv…], "env": {"BOAT_SANDBOX_DEFAULTS": "…"}, "copies": "…"}`: the command run instead of `~/bin/boat-sandbox`, extra environment for it, and a file that receives every copy the sidebar makes, one JSON string per line, instead of the clipboard) before the window opens, so the window never reaches your boat account, not even for the background listing: that command refuses every mode and the Boat section stays hidden. `-NSAppSleepDisabled YES` keeps macOS App Nap off for that window only: a hidden window that naps runs no timers while idle, and in one run it took longer than the 50 ms load budget at the lifecycle scenario's Reload plugins. The window runs a copy of the plugin: a linked folder reloads on every save, which would reset the plugin's window state in the middle of a scenario. The switch scenario needs the window's only session and adds one named `SwitchTwo`, so run it first; the lifecycle scenario creates two extra tabs, exits the last one's shell and ends with the palette's Reload plugins; the agent scenario writes three recordings to `/tmp/sessions-sidebar-agent-*.jsonl` and opens three tabs and one extra session without closing any pane; the add-host scenario writes request files into the isolated plugin data folder (it reads `TERN_CONFIG_DIR`) and adds a loopback remote host `boat-test`; the remove-host scenario adds a loopback host `rm-host` and removes it; the width scenario switches to Always expanded and opens two tabs, a session named `WidthTwo`, a loopback remote host `widthbox` and a tab there. The boat, reattach and boat-rows scenarios point that key at a fake shell script they write into the isolated plugin data folder, add loopback remote hosts (three, two, `re-box` and four) and disconnect them, remove their files, records and the listing cache at the end and put back the key as they found it. Their sidebar selectors start with `.tn-pane:not(.off)`: every tab keeps its sidebar, off screen while the tab is hidden, and a bare selector can hit a hidden one. The reattach scenario also reads Tern's log in `STENCIL_LOG_DIR`; boat-rows writes two recordings to `/tmp/sessions-sidebar-boat-*.jsonl` and removes them. Only boat-rows closes a session: the only one of its loopback host `rows-none`. Afterwards run `tern ctl --control "$test_dir/control.sock" quit`, then `pkill -f "$test_dir/control.sock"` and `pkill -f "tern daemon --socket $test_dir/daemon.sock"`, and delete `$test_dir`. Tern's [script reference](https://docs.stencil.so/tern/scripts/) documents `ctl`.
